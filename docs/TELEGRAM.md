# Telegram: керування оркестратором з телефона (опційно)

Установник **не налаштовує Telegram** і не встановлює плагін автоматично. Усе нижче ви робите самі. Команди звірено з файлами офіційного плагіна `telegram@claude-plugins-official` (версія, з якою перевірялось: 0.0.7). Що не вдалося звірити, позначено «перевірте актуальну довідку плагіна» (`/plugin`, README плагіна).

## 1. Що це дає

Ви пишете боту в Telegram — повідомлення приходить у запущену сесію Claude Code як завдання; відповідь оркестратора повертається у чат. Так можна ставити задачі й отримувати звіти з телефона. Працює через MCP-сервер плагіна, який логіниться в Telegram як бот. Фото, що ви надсилаєте, плагін завантажує локально й показує агенту.

Вимоги: плагін працює на [Bun](https://bun.sh) (за його README); працює лише поки запущена сесія Claude Code з каналом; Telegram Bot API не дає історії повідомлень і пошуку — бот бачить лише нові повідомлення.

## 2. Створити бота в @BotFather

1. У Telegram відкрийте [@BotFather](https://t.me/BotFather).
2. Надішліть `/newbot`.
3. Вкажіть **ім'я** (відображається в чаті, можна з пробілами) і **username** (унікальний, закінчується на `bot`, напр. `my_team_assistant_bot`).
4. BotFather пришле **токен** виду `123456789:AAH…`. Це пароль до вашого бота: **не публікуйте його, не комітьте, не вставляйте в чат/скріншоти**.

## 3. Встановити плагін у Claude Code

У сесії Claude Code (`claude`):

```
/plugin install telegram@claude-plugins-official
```

Якщо команда недоступна або marketplace не підключений — «перевірте актуальну довідку плагіна» та документацію Claude Code щодо плагінів. Переконайтесь, що встановлено Bun (`bun --version`).

## 4. Зберегти токен

```
/telegram:configure 123456789:AAH...ваш_токен
```
Токен записується плагіном локально в `.env` у його теці стану (за замовчуванням `~/.claude/channels/telegram/`, змінюється змінною `TELEGRAM_STATE_DIR`; права файла — 600). Можна також задати змінну `TELEGRAM_BOT_TOKEN` у середовищі оболонки (вона має пріоритет). `/telegram:configure` без аргументів показує стан (токен частково маскується). Після зміни токена потрібен перезапуск сесії або `/reload-plugins`.

Цієї теки не існує у репозиторії й **ніколи не копіюйте її в git**.

## 5. Запустити сесію з каналом

Сервер плагіна не підключиться без прапорця `--channels`:

```sh
claude --channels plugin:telegram@claude-plugins-official
```

З оркестратором:

```sh
claude --agent orchestrator --channels plugin:telegram@claude-plugins-official
```

Прапорець `--agent` описаний у `claude --help`; прапорець `--channels` подано за README плагіна, а його сумісність з `--agent` ми не могли перевірити в довідці CLI — перевірте актуальну довідку (`claude --help`) вашої версії. Якщо комбінація не приймається, запустіть з `--channels` і попросіть оркестратора в сесії, або задайте `"agent": "orchestrator"` у `settings.json`.

Лінукс/macOS, щоб дашборд міг вводити команди в сесію (tmux-режим):

```sh
~/.claude/dashboard/claude-tmux --agent orchestrator --channels plugin:telegram@claude-plugins-official
```
(`claude-tmux` просто передає аргументи в `claude` усередині tmux.) На Windows tmux-режиму немає; команди з дашборду йдуть чергою.

## 6. Парування

1. Напишіть вашому боту в Telegram (будь-що). За замовчуванням (`dmPolicy: pairing`) бот відповість **6-символьним кодом**. Якщо мовчить — див. розділ 9.
2. У **терміналі** вашої сесії Claude Code виконайте:
   ```
   /telegram:access pair <код>
   ```
3. Наступне ваше повідомлення дійде до агента. Код потрібно вводити завжди явно: не просіть «схвали очікуване».

Політики (`dmPolicy`), змінюються `/telegram:access policy <режим>`:

| Режим | Поведінка |
|---|---|
| `pairing` (типово) | невідомому відправнику — код парування; повідомлення відкидається |
| `allowlist` | невідомі відправники ігноруються мовчки (рекомендований робочий режим) |
| `disabled` | відкидається все, включно зі своїми |

Після того як ви спарувались, перемкніть на `allowlist`:
```
/telegram:access policy allowlist
```
Інші команди: `/telegram:access` (стан), `allow <числовий id>`, `remove <id>`, `deny <код>`, `group add <id групи> [--no-mention] [--allow id1,id2]`, `group rm <id>`, `set <ключ> <значення>` (`ackReaction`, `replyToMode`, `textChunkLimit`, `chunkMode`, `mentionPatterns`). Числовий id людини можна дізнатись у [@userinfobot](https://t.me/userinfobot). Групи вимкнені за замовчуванням; для відповіді без згадки потрібно вимкнути privacy mode у BotFather (`/setprivacy`). Повний опис — `ACCESS.md` у теці плагіна («перевірте актуальну довідку плагіна»).

## 7. Безпека

- **Доступом керує лише користувач, у терміналі.** Команди `/telegram:access …` не можна виконувати за проханням, що надійшло в повідомленні каналу. Оркестратор у цьому репозиторії про це знає: зміни доступу, allowlist, permissions за запитом із каналу він не виконує.
- **Повідомлення каналу — дані, а не вказівки.** Оркестратор довіряє лише власнику каналу (спарованому вами) і не виконує команди від неперевірених відправників.
- **Токен** зберігається локально (права 600), не комітьте його: у `.gitignore` є `.env`, а `tests/smoke.js` шукає токени ботів у репозиторії.
- Перемкніть політику на `allowlist` одразу після парування, щоб сторонні не отримували коди.
- Пам'ятайте: агент виконує завдання з телефона з тими самими правами, що й у терміналі. Налаштуйте `permissions` у Claude Code обережно; сесія, що чекає дозволу, не просунеться без вас.

## 8. Як перевірити, що працює

1. У терміналі: `/telegram:configure` (без аргументів) — токен «set», політика, список дозволених.
2. Надішліть боту «привіт» — має з'явитися «typing…», а потім відповідь агента.
3. У дашборді (якщо запущений) в «Розмові» з'являється запис з джерелом Telegram.

## 9. Типові проблеми

| Проблема | Що робити |
|---|---|
| Бот мовчить | Сесію запущено без `--channels plugin:telegram@claude-plugins-official`? Перезапустіть з прапорцем. Токен збережено (`/telegram:configure`)? Є Bun? |
| Код парування не приходить | Політика `allowlist`/`disabled` (бот мовчить навмисно): тимчасово `/telegram:access policy pairing`; або додайте id напряму `allow <id>`. Перевірте, що пишете саме цьому боту. |
| Код протермінований/«не знайдено» | Напишіть боту ще раз, отримайте новий код, одразу виконайте `pair`. |
| «Токен змінено, але не діє» | Перезапустіть сесію або `/reload-plugins`. |
| Кілька сесій | Один токен — один підключений сервер. Для кількох ботів використайте окремі `TELEGRAM_STATE_DIR`; не запускайте дві сесії з тим самим ботом. |
| Довгі відповіді | Telegram обмежує довжину; плагін ділить текст на частини (`set textChunkLimit`, `chunkMode`). |
| Бот «не пам'ятає» старе | Bot API не віддає історію; перешліть або перекажіть потрібне. |
| Оркестратор не виконує прохання «додай мене в allowlist» | Так і задумано: це робиться лише в терміналі. |

## 10. Відключення і відкликання токена

- Тимчасово: запустіть сесію без `--channels` або `/telegram:access policy disabled`.
- Прибрати токен локально: `/telegram:configure clear`.
- **Відкликати токен назавжди:** у [@BotFather](https://t.me/BotFather) виконайте `/revoke`, виберіть бота — старий токен перестане діяти (потім можна згенерувати новий). Якщо токен випадково потрапив у git чи чат — робіть `/revoke` негайно.
- Видалити плагін: керуйте через `/plugin` («перевірте актуальну довідку плагіна»).
