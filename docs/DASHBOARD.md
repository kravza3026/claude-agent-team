# Дашборд

Локальна веб-панель для Claude Code. Показує, що роблять агенти, скільки ви витратили з лімітів, і дозволяє надсилати команди з браузера. Працює на Node без залежностей; three.js лежить локально в `dashboard/vendor/` (з інтернету нічого не вантажиться).

## Запуск

| ОС | Команда |
|---|---|
| Linux/macOS | `node ~/.claude/dashboard/start.js` або `~/.claude/dashboard/start.sh` |
| Windows | `node "%USERPROFILE%\.claude\dashboard\start.js"`, `start.cmd` або `start.ps1` |

`start.js` запускає сервер у фоні (лог — `dashboard/server.log`), чекає готовності й відкриває браузер (`xdg-open` / `open` / `start`). Опції: `--port N`, `--no-open`, `--foreground` (сервер у цьому ж процесі), `--stop` (зупинити сервер, запущений цим скриптом; PID у `dashboard/server.pid`). Автозапуск при вході: `install --service` (див. INSTALL.md). Зупинка: `node start.js --stop`; якщо не вийшло — знайдіть процес `node …/dashboard/server.js` (Linux/macOS: `pkill -f dashboard/server.js`; Windows: Диспетчер завдань або `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | ? CommandLine -like '*dashboard*server.js*' | % { Stop-Process $_.ProcessId }`), або `systemctl --user stop agents-dashboard` / `launchctl bootout …` / `schtasks /End /TN ClaudeAgentTeamDashboard`.

## Можливості

- **Події агентів у реальному часі:** запуск/завершення субагентів, виклики інструментів, помилки, сповіщення про дозволи; фільтри за типом, пошук, стрічка «Розмова» (запити з терміналу, Telegram і дашборду + відповіді).
- **Сцена/схема:** 3D-пайплайн (оркестратор → підготовка → розробка → перевірка) з «пакетами» завдань, станами, таймерами; клік по агенту показує його навички й інструменти; запасний 2D-режим (SVG), якщо WebGL недоступний. Масштаб: кнопки ＋/－/◎ та Ctrl(⌘/Shift)+колесо.
- **KPI:** активні агенти, виклики, помилки, команди, сесії, ліміт 5 год, остання подія; таймлайн активності; таблиця агентів зі статистикою; вкладка «План» (кроки з `log.js`).
- **Ліміти й витрати:** відсотки лімітів (5 год / 7 днів) і контекст беруться зі `statusLine` (`statusline.js` → `status.json`); токени (вхід/вихід/кеш) сервер рахує з транскриптів `projects/**/*.jsonl` у фоні, за вікнами 5 год / 24 год / 7 днів, моделями й проєктами.
- **Команди з дашборду:** поле «Команди» → доставка в основну сесію (див. режими нижче).
- **Вибір моделі:** (1) поточна сесія — `/model <алиас>` у термінал через tmux (Linux/macOS), (2) типова модель — ключ `model` у `settings.json` (лише за вашим кліком і підтвердженням), (3) моделі агентів — рядок `model:` у `agents/<агент>.md`. Допустимі значення — з білого списку `fable|opus|sonnet|haiku` (+ `inherit`/`default`). Перед записом робиться копія в `dashboard/backups/` (10 останніх).
- **Мова інтерфейсу (UA/EN):** перемикач `UA | EN` у шапці, зміна миттєва (без перезавантаження, стан сцени/вкладок зберігається). Вибір пишеться в `localStorage` браузера (ключ `lang`); без нього береться мова браузера (`uk*` → українська, інакше англійська), запасна — українська. Словники — `dashboard/locales/uk.json` і `en.json` (плоскі ключі, 261 штук; віддаються `GET /locales/uk.json|en.json`). При перемиканні сторінка надсилає `POST /lang {"lang":"uk|en"}` (Host/Origin + `X-Token`, лише значення `uk|en`, інакше 400, без токена 403); сервер записує мову у файл `dashboard/lang` і використовує її для системних сповіщень та текстів помилок API (відповідь містить код `code` і переклад `why`); поточну мову віддає `GET /state` (поле `lang`). Дані не перекладаються (команди, відповіді Claude, деталі інструментів, назви проєктів). Перевірка словників: `node dashboard/tools/check-i18n.js` (паритет ключів, непорожні значення, усі ключі з `index.html`/`server.js` існують). Нова мова: скопіюйте `locales/en.json` у `locales/<код>.json`, перекладіть, додайте код у `LANGS`/`LOCALES` в `index.html`, у `LANGS` і маршрут `/locales/` в `server.js`, кнопку в `#langSeg` та ключ `lang.<код>`.
- **Ролі й чітка відповідальність:** у дашборді оркестратор і 21 роль (склад і зв'язки задає `dashboard/team.json`) із чітким розподілом обов'язків. Агенти без ролі (напр. вбудований `general-purpose`) на схемі не показуються: завдання слід доручати спеціалізованим ролям, а оркестратор делегує лише своїм ролям. Імена з викликів `Agent` нормалізуються (старі імена `frontend-developer`, `backend-developer`, `developer`, `reviewer` — псевдоніми нових ролей), а завдання «у черзі» без старту понад 15 хв зі стрічки завдань прибираються.
- **Схема:** режими «Сцена»/«Схема»; кнопка ⛶ — схема на весь екран, кнопка ↔/↕ — вертикальна або горизонтальна розкладка (вертикальна показує логічні зв'язки між агентами: передача роботи, повернення на доопрацювання, звіт оркестратору); фон у стилі n8n (точкова сітка).
- **Сповіщення:** завершення агента та збій кроку плану: Linux `notify-send`, macOS `osascript`, Windows PowerShell (balloon). Вимкнути: кнопка 🔔 або створіть порожній файл `dashboard/mute`. Якщо засобу нема — тихо пропускається.

## Порт, токен, безпека

- Сервер слухає **лише 127.0.0.1**. Порт: `--port` у `start.js`, змінна `AGENTS_DASHBOARD_PORT` (також приймається `PORT`), типово 7777. Порт зайнятий → сервер пише підказку й завершується.
- Кожен запит перевіряє заголовок `Host` (лише `127.0.0.1:<порт>`/`localhost:<порт>`); POST-запити додатково — `Origin`, `Content-Type: application/json` і токен.
- Токен — випадкові 24 байти в `dashboard/.token` (створюється при першому запуску; на Linux/macOS права `600`; на Windows POSIX-права не діють — файл у вашому профілі). Сторінка отримує токен від самого сервера.
- Поля команд обмежені за довжиною, керівні символи видаляються; у черзі не більше 20 невиконаних команд, TTL — 30 хв.
- Команда з дашборду для агентів — це введення користувача, але НЕ дає права змінювати налаштування доступу/permissions/`settings.json` або обходити правила git (це прописано в `deliver.js` і оркестраторі).
- Докладніше: [SECURITY.md](SECURITY.md).

## Режими доставки команд

1. **Черга (усі ОС).** Команда пишеться в `inbox.jsonl`. Хук `deliver.js` (UserPromptSubmit/PreToolUse/Stop) віддає її основній сесії як додатковий контекст з позначкою `[джерело: dashboard, id …]`; підтвердження — `acks.jsonl`. Команда в бездіяльній сесії чекає наступної активності (або моменту, коли хук `Stop` «розбудить» агента).
2. **tmux (лише Linux/macOS, якщо встановлено tmux).** Запускайте Claude через `dashboard/claude-tmux [аргументи]` (напр. `claude-tmux --agent orchestrator`). Хуки запам'ятовують панель сесії в `panes.json`; дашборд вводить команду через `tmux send-keys` лише коли сесія бездіяльна, не чекає дозволу й у терміналі нема діалогу; інакше автоматично — черга. Текст отримує префікс `[dashboard:<id>]`. На Windows режим тихо вимкнений.

## Як це працює

```
Claude Code ──хуки──► hook.js  ──► events.jsonl ──► server.js ──SSE──► браузер (index.html)
            ──хук───► deliver.js ◄── inbox.jsonl ◄── POST /command ◄── браузер
            ──statusLine─► statusline.js ──► status.json ──► ліміти
транскрипти projects/**/*.jsonl ──► server.js (підрахунок токенів) ──► usage-cache.json
```

Файли даних лежать у `dashboard/`: `events.jsonl` (ротація при >5 МБ), `inbox.jsonl`, `acks.jsonl`, `panes.json`, `status.json`, `usage-cache.json`, `.token`, `mute`, `lang`, `server.log`. Вони створюються під час роботи й не входять до репозиторію (`.gitignore`).

Кроки плану оркестратор пише через `node dashboard/log.js <агент> <queued|running|done|failed> "<опис>"` (нічого не робить і не падає, якщо дашборд не запущено).

## Приватність

- Усе зберігається локально; дашборд нікуди не надсилає дані й не завантажує зовнішніх ресурсів.
- `hook.js` пише стислі події: назва інструмента, обрізана «деталь» (команда до 160 символів, шлях файла), текст відповіді агента (до 4000 символів) та ваші запити (до 400). Перед записом **редагуються секрети**: значення після `api_key|secret|token|password|APP_KEY|authorization`, токени вигляду `sk-…`, `ghp_…`, `xox…`, `base64:…`. Редагування евристичне — не вставляйте секрети в запити; за потреби вимкніть збір (див. нижче).
- Облік токенів читає транскрипти Claude Code лише для підрахунку (`usage`), їхній зміст не копіюється.
- Вимкнути збір: `install --uninstall` або видалити наші хуки з `settings.json`; очистити дані: `--uninstall --purge` або видалити `events.jsonl` та ін. у `dashboard/`.

## Обмеження за ОС

| | Linux | macOS | Windows |
|---|---|---|---|
| Події, схема, ліміти | так | так | так |
| Черга команд | так | так | так |
| tmux-режим, вибір моделі для поточної сесії | так | так | ні |
| Сповіщення | `notify-send` (пакет libnotify) | `osascript` | PowerShell balloon (залежить від налаштувань сповіщень Windows) |
| Назва проєкту з теки транскрипту | так | best-effort | best-effort (`C--Users-…`) |
| Права `600` на токен | так | так | не застосовується |

Проєкт у подіях визначається з імені теки транскрипту Claude Code (формат залежить від ОС); якщо формат невідомий, показується ім'я теки як є.
