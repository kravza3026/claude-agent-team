# Підключення Claude Code

Покрокова інструкція: як поставити Claude Code, увійти в акаунт і запустити команду агентів з цього набору. Офіційна документація — головне джерело: <https://docs.anthropic.com/en/docs/claude-code>; усе, що змінюється швидко (команди встановлення, назви пакетів, меню `/…`), перевіряйте там.

Позначки: **[звірено]** — команду або прапорець підтверджено виводом `claude --help` / `claude <команда> --help` (Claude Code 2.1.309, Linux) на машині автора; **[перевірте]** — не вдалося звірити з довідкою CLI, перевірте актуальну довідку.

## 1. Що потрібно

- **Акаунт Anthropic:** підписка Claude (вхід через браузер) **або** API-ключ (оплата за використання). Без одного з них Claude Code не працюватиме.
- **Node.js 18+** потрібен лише для дашборду й установника цього набору (не для самого Claude Code, якщо ви ставите нативний варіант).
- **git** — щоб клонувати репозиторій набору.
- Терміналом: Linux/macOS — будь-який; Windows — PowerShell (або WSL; вимоги до оболонки на Windows дивіться в офіційній документації).

## 2. Встановлення Claude Code

Є два шляхи. Завжди беріть точні команди з офіційної сторінки встановлення: вона оновлюється.

**Нативний інсталятор (рекомендовано в офіційній документації) [перевірте].** Команду/скрипт для вашої ОС (Linux, macOS, Windows) наведено в розділі встановлення офіційної документації; ми свідомо не копіюємо сюди URL скриптів і не радимо `curl … | sh` з пам'яті. Після того як `claude` з'явився в PATH, наступні версії можна ставити так: `claude install [stable|latest|<версія>]` **[звірено]** (опція `--force` — примусове перевстановлення **[звірено]**).

**Через npm [перевірте].** Варіант для тих, у кого вже є Node.js 18+: `npm install -g @anthropic-ai/claude-code`. Назву пакета й актуальність цього способу підтвердьте в офіційній документації (розділ встановлення). Не використовуйте `sudo npm …`; якщо npm вимагає прав, налаштуйте префікс для глобальних пакетів за документацією npm.

**Перевірка:**
```sh
claude --version        # [звірено] друкує, напр., «2.1.309 (Claude Code)»
claude doctor           # [звірено] перевірка стану установки
```
Windows PowerShell: ті самі команди. Якщо команда не знайдена — розділ 7.

**Оновлення.** `claude update` (синонім `claude upgrade`) **[звірено]**: перевіряє оновлення й ставить їх; якщо Claude Code встановлено менеджером пакетів (npm тощо), оновлення йде через нього (так сказано в `claude update --help`). Альтернатива — повторно виконати команду встановлення.

## 3. Вхід в акаунт і ключі

**Підписка Claude (браузер).** Запустіть `claude` і виконайте `/login` **[перевірте]** (команда сесії). Відкриється браузер для входу. Із терміналу доступні і `claude auth login`, `claude auth status`, `claude auth logout` **[звірено]**. Якщо браузер не відкрився — скопіюйте посилання, яке показав Claude Code, і відкрийте його вручну (розділ 7).

**Альтернатива — API-ключ.** Claude Code читає ключ зі змінної середовища `ANTHROPIC_API_KEY` **[звірено: згадується в `claude --help` для режиму `--bare`; загальну поведінку підтвердьте в документації]**. Задавайте її **в середовищі користувача**, а не в репозиторії:

- Linux/macOS (bash/zsh), на одну сесію: `export ANTHROPIC_API_KEY="…ваш ключ…"` у терміналі. Постійно: додайте цей рядок у `~/.bashrc` або `~/.zshrc` (файл не потрапляє в git, перевірте права `chmod 600`).
- Windows PowerShell, на одну сесію: `$env:ANTHROPIC_API_KEY = "…ваш ключ…"`. Постійно для користувача: `[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", "…ваш ключ…", "User")` і відкрити нове вікно.
- Не вставляйте реальний ключ у приклади, скрипти, історію команд спільного комп'ютера, чати й скріншоти.

**Перевірка:** у сесії `/status` **[перевірте]** або в терміналі `claude auth status` **[звірено]**. **Вихід:** `/logout` **[перевірте]** або `claude auth logout` **[звірено]**.

Для довготривалого токена підписки є `claude setup-token` **[звірено: «Set up a long-lived authentication token (requires Claude subscription)»]**; призначення й безпечне зберігання токена — за офіційною документацією.

**Безпека ключів.** Ключі й токени: не комітити (файли `.env` у `.gitignore`), не друкувати у відповідях і логах, не вставляти в промти. Агенти цього набору не читають `.env`; якщо ключ усе ж потрапив у git або чат — відкличте його в консолі Anthropic й створіть новий.

## 4. Перший запуск у теці проєкту

1. `cd ваш-проєкт` і виконайте `claude`.
2. **Довіра до теки.** При першому запуску в новій теці Claude Code питає, чи довіряєте ви їй. Погоджуйтеся лише для своїх проєктів: у довіреній теці можуть застосовуватися налаштування й хуки проєкту.
3. **Режими дозволів.** За замовчуванням Claude питає дозволу на дії (читання/запис/команди). Прапорець `--permission-mode` приймає значення `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk`, `plan` **[звірено]**; для початку залишайте типовий (запитувати). Не вмикайте `bypassPermissions` / `--dangerously-skip-permissions` поза ізольованим середовищем. Правила `deny` у ваших `settings.json` не послаблюйте: набір їх не змінює.
4. Введіть запит у полі промта. Корисні команди сесії **[перевірте]**: `/help` (довідка), `/model` (вибір моделі; прапорець запуску `--model <модель>` **[звірено]**), `/permissions` (перегляд і зміна правил дозволів). Модель можна змінити і з дашборду — картка «Модель Claude» (див. [DASHBOARD.md](DASHBOARD.md)).

## 5. Запуск команди агентів

Після установки набору ([INSTALL.md](INSTALL.md)):

```sh
cd ваш-проєкт
claude --agent orchestrator        # [звірено] --agent <agent>: агент для поточної сесії
```
Приклад першого завдання: «Проаналізуй структуру проєкту й запропонуй план додавання сторінки контактів із формою; нічого поки не змінюй». Оркестратор викличе планувальника, а за вашого погодження — решту ролей (див. [AGENTS.md](AGENTS.md)).

Коли достатньо звичайного `claude`: для швидких питань, дрібних правок в одному файлі, ознайомлення з кодом — оркестрація тут зайва.

**Перевірка, що хуки дашборду працюють.**
1. Запустіть дашборд: `node ~/.claude/dashboard/start.js` (Windows: `node "$env:USERPROFILE\.claude\dashboard\start.js"`).
2. У проєкті запустіть `claude` (або оркестратор) і виконайте будь-яку дію, наприклад попросіть прочитати файл.
3. У дашборді (http://127.0.0.1:7777) мають з'явитися події. Якщо ні — [TROUBLESHOOTING.md](TROUBLESHOOTING.md), розділ «Хуки не спрацьовують». Докладно про дашборд: [DASHBOARD.md](DASHBOARD.md).

**Сесія в tmux (лише Linux/macOS).** `~/.claude/dashboard/claude-tmux --agent orchestrator` запускає Claude у tmux-сесії; завдяки цьому дашборд може вводити команди прямо в бездіяльну сесію (без tmux вони чекають у черзі й доставляються хуками). Потрібен встановлений `tmux`. На Windows цього режиму нема.

## 6. Обмеження й поради

- **git, що змінює стан** (`add`, `commit`, `push`, `reset`, `switch` …), виконуєте ви. Агенти не комітять і не пушать. Щоб виконати команду в самій сесії, введіть її з префіксом `!`, наприклад `! git status` **[перевірте]**; або робіть це в окремому терміналі.
- Агенти не читають `.env` і не друкують секрети; не просіть їх про це.
- Одночасно запускайте не більше одного браузера Playwright (обмеження пам'яті).
- Для довгих завдань стежте за лімітами й витратами в дашборді; змінюйте модель агентів (`model:` у `agents/*.md`) під бюджет.
- Telegram-керування з телефона — окрема інструкція: [TELEGRAM.md](TELEGRAM.md).

## 7. Типові проблеми

| Проблема | Що робити |
|---|---|
| `claude: command not found` | Відкрийте нову оболонку (PATH оновлюється при запуску). Перевірте `command -v claude` (Windows: `where claude`). Нативна установка кладе файл у теку користувача (зазвичай це тека на кшталт `~/.local/bin`; точне місце — в офіційній документації): додайте її в PATH. Якщо ставили через npm і Node керує nvm — активуйте потрібну версію Node (`nvm use`) і перевірте глобальний префікс npm (`npm config get prefix`) та його теку `bin` у PATH. |
| Помилка входу / браузер не відкрився | Скопіюйте посилання з терміналу й відкрийте вручну в браузері; на віддаленому сервері/WSL відкрийте його на своїй машині. Спробуйте `claude auth login` **[звірено]**; перевірте `claude auth status`. |
| Корпоративна мережа / проксі | Claude Code потребує доступу до інтернету. Змінні `HTTPS_PROXY`/`HTTP_PROXY` — стандартний спосіб для CLI, але для Claude Code **[перевірте]** в офіційній документації розділ про мережеві налаштування/проксі; не вигадуйте інших змінних. |
| Оновлення не ставиться | `claude update` **[звірено]**; при встановленні через менеджер пакетів оновлюйте ним; `claude doctor` покаже проблеми установки. |
| Windows | Запускайте у PowerShell (не в «Блокноті»/старому cmd для скриптів). Якщо скрипти заборонені — див. [INSTALL.md](INSTALL.md), розділ 3 (ExecutionPolicy). Альтернатива — WSL (Linux-інструкції діють усередині WSL; дашборд відкривайте за http://127.0.0.1:порт у браузері Windows, перевіряючи, що порт доступний). |
| Агенти/хуки не бачать `node` | [TROUBLESHOOTING.md](TROUBLESHOOTING.md), розділ «Node не знайдено». |
